# Copilot 风格对齐专题迭代记录

## 1. 目标与范围
- 目标：将 DeepSeek 插件在聊天主流程中的体验，对齐到 Copilot 风格或更优。
- 范围：Working 过程展示、生成文件确认流程、Keep/Undo 审核链路、自动修复闭环、噪音治理。
- 原则：单一确认入口、可回退、低噪音、可解释、可持续迭代。

## 2. 关键设计原则（最终方向）
- Working 仅展示当前关键动作，不展示长日志。
- 最终只保留一套确认语义：Keep / Keep All / Undo / Undo All。
- 文件级确认与修改点级确认并存，但语义一致。
- 无真实改动不进入确认队列。
- 自动修复只在“已应用且验证失败”时进入闭环。

## 3. 本轮沟通与迭代纪要

### 3.1 第一阶段：显示策略与映射优先
- 用户诉求：聊天主区不要代码墙，优先显示文件清单和可操作入口。
- 实施结果：
  - 引入生成文件映射优先模式。
  - 生成正文支持隐藏/折叠/完整三档。
  - 支持路径点击打开真实文件或虚拟预览。

### 3.2 第二阶段：Working 区与流程降噪
- 用户诉求：Working 像 Copilot，过程临时显示，结束后收敛。
- 实施结果：
  - 引入 Working 区、阶段状态与简短总结。
  - 去除重复 started 卡片，弱化过程噪音。
  - 完成后自动收敛，避免持续刷屏。

### 3.3 第三阶段：文件确认能力增强
- 用户诉求：增加单文件对比/替换，后续增加 Keep/Undo 累计队列。
- 实施结果：
  - 增加文件级“对比/替换此文件”入口。
  - 增加 pending edits 队列。
  - 支持 Keep/Undo 单项与 Keep All/Undo All 批量。

### 3.4 第四阶段：预览与路径漂移问题修复
- 用户反馈：
  - 全局预览只能打开第一个文件。
  - 路径漂移误判导致回滚。
- 实施结果：
  - 全局预览支持选择任意文件与依次预览。
  - 放宽漂移判定，避免 basename 误报。
  - 仅保留真正越界写入的拦截。

### 3.5 第五阶段：确认入口去重（单一语义）
- 用户诉求：对比/替换/应用 与 Keep/Undo 本质重复，应保留一套。
- 实施结果：
  - 停用生成面板中的重复确认入口。
  - 改为直接进入 Keep/Undo 队列。
  - 统一“先审后收”路径。

### 3.6 第六阶段：零改动噪音修复
- 用户反馈：+0/-0 仍显示 Keep/Undo，不合理。
- 实施结果：
  - 后端新增有效改动判定。
  - 前端渲染前二次过滤无效条目。
  - 无改动时不显示确认队列，仅保留状态说明。

### 3.7 第七阶段：Working 人性化收敛
- 用户反馈：Working 不应固定展示日志，应只表达当前动作与结果摘要。
- 实施结果：
  - 过程文案简化为“当前动作”。
  - 编译细节降级为非主信息。
  - 结束后保留一句概要总结并收敛。

### 3.8 第八阶段：补充修改点级 Keep/Undo
- 用户补充：除文件级 Keep/Undo 外，需支持文件内单点独立确认。
- 当前方向：
  - 保持文件级主动作。
  - 在当前选中文件下展示修改点列表，支持单点 Keep/Undo。

## 4. 当前状态结论
- 已完成：
  - 单一确认语义主路径搭建。
  - Working 降噪与摘要化。
  - 自动修复闭环准入条件收敛。
  - 零改动条目过滤。
- 待持续优化：
  - 修改点级 Keep/Undo 交互稳定性与命中率。
  - Working 动态文案的场景化精准度。
  - 队列顺序与多轮叠加时的可读性。
