## 本次变更概述

### Bug 修复

#### B-7: 右键菜单命令在 API 模式下全部失效
- **根因：** `commands/index.ts` 中的 `dispatch()` 函数调用 `await ping()`（bridge 专用），导致所有右键命令（解释/修复/重构/生成测试/生成文档/提问）在使用 DeepSeek API 或 Ollama 时直接报错 "Bridge 未运行"。
- **修复：** 移除 `ping()` 调用，改为 `getActiveProvider().available()`，路由逻辑与 inline chat 保持一致。
- **附带修复：** `applyDiff()` 同样硬编码了 `ping()` + `chat()`，一并迁移到 `provider.chat()` 抽象层。

### P3-4: 测试生成与运行

#### 1. `detectTestFramework()` — 测试框架自动检测

新增 `commands/index.ts` 内部辅助函数：

| 语言 | 检测方式 | 默认框架 |
|------|----------|----------|
| TypeScript / JavaScript | 读 `package.json` devDependencies：vitest > jest > mocha > jasmine | Jest |
| Python | 检测 `pytest.ini` / `setup.cfg` / `pyproject.toml` | pytest |
| Rust | 检测 `Cargo.toml` | cargo test |
| Go | 检测 `go.mod` | go test |
| Java | 无文件检测，直接默认 | JUnit / mvn test |
| C# | 无文件检测，直接默认 | NUnit / dotnet test |
| C/C++ | 无文件检测，直接默认 | Google Test / ctest |

#### 2. `genTest()` — 框架感知 prompt

旧版：通用 prompt，未指定框架  
新版：
- 调用 `detectTestFramework()` 获取框架名 + 运行命令
- 在 Chat 面板标题行显示检测到的框架（如 `🧪 生成测试 · main.ts · Vitest`）
- 建议测试文件名（`main.test.ts`）随 display 一同展示
- prompt 要求 LLM：按框架规范组织测试块、覆盖正常/边界/异常、注释测试文件路径、最后一行说明运行命令

#### 3. `deepseek.runTests` 命令 — 在终端运行测试

- 检测当前工作区测试框架
- 弹出 InputBox 让用户确认/编辑命令（预填检测结果）
- 复用名为 `DeepSeek Tests` 的集成终端（不存在则新建）
- 设置终端 cwd 为工作区根目录

#### 4. webview.js — slash 命令更新

| 命令 | 行为 |
|------|------|
| `/tests` | 发给 LLM 生成测试（已有，描述更新）|
| `/test` | 新增：`postMessage({ type: 'runCommand', command: 'deepseek.runTests' })` → 在终端运行测试 |

## 架构变化

### commands/index.ts 依赖关系

```
之前：
  dispatch() → ping() [bridge only] → bridge-client.chat()
  applyDiff() → ping() [bridge only] → bridge-client.chat()

之后：
  dispatch() → getActiveProvider().available() → _deepseek.askChat (provider-agnostic)
  applyDiff() → getActiveProvider().available() → provider.chat()
  runTests() → detectTestFramework() → vscode.Terminal.sendText()
```
