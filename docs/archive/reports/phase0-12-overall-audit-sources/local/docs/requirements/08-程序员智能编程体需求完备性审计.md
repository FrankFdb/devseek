# 程序员智能编程体需求完备性审计

文档编号：REQ-08
最后更新：2026-06-18
状态：活跃需求审计
用途：确认 DevSeek 需求是否覆盖程序员使用智能编程体时应有的核心能力，并把漏项回填到 [02-顶级编程智能体需求基线.md](02-顶级编程智能体需求基线.md)。

## 1. 审计结论

本轮重新对照 Claude Code、OpenAI Codex、GitHub Copilot，并补充 Cursor、Devin Desktop / Windsurf Cascade、Cline、Aider、Gemini CLI 后，结论如下：

1. DevSeek 主干需求已经覆盖顶级编程智能体的核心：Plan、工具、权限、文件变更、验证、记忆、历史任务、Provider、QualityGate。
2. 之前不够显式的缺口集中在程序员高频工程场景：代码库符号导航、忽略规则、并发冲突、工程环境、语言/运行时支持矩阵、依赖安装、外部文档 grounding、成本预算、多根工作区、预览/Notebook、任务回放评测、运行形态和跨平台。
3. 本轮已将这些缺口补入 REQ-A/D/E/G/H/M/N，并把后续设计落点放入 [../architecture/09-程序员工程完整性架构设计.md](../architecture/09-程序员工程完整性架构设计.md) 和 [../architecture/10-运行形态与界面解耦架构设计.md](../architecture/10-运行形态与界面解耦架构设计.md)。
4. 经过本轮补强，需求基线已能作为 DevSeek 后续重构的完整目标集合；后续新增需求应先判断是否属于这些 REQ 的细化，而不是继续扩散新主题。

## 3. 本轮新增或补强需求

| 新增/补强 | 原因 |
| --- | --- |
| REQ-A6 | Aider、Copilot、Cline 都说明大型仓库不能只靠全文搜索，需要 repository map、索引和符号导航 |
| REQ-D6 | Cascade `.codeiumignore`、Cline `.clineignore`、Copilot content exclusion 都证明忽略规则是 Agent 安全边界 |
| REQ-D7 | Web Search、MCP、issue、README、依赖文档进入上下文后，必须防 prompt injection |
| REQ-E6 | 本地 Agent 与用户同时编辑文件是高频风险，必须有文件版本和冲突保护 |
| REQ-G6 | 程序员经常从 Problems、Terminal、选区、截图和历史任务进入工作流 |
| REQ-H5 | Monorepo、多仓库和多根工作区是现代工程常态，必须明确 root 边界 |
| REQ-M1~M7 | 覆盖环境、依赖、预览、当前文档、成本、任务回放、issue/PR/TODO 来源等真实工程场景 |
| REQ-M8 | 编程智能体必须知道自己对不同语言的能力边界，按语言声明索引、诊断、格式化、构建、测试、运行、依赖管理和降级策略 |
| REQ-N | 编程智能体不能绑定单一 IDE，必须支持显示/功能分离、多入口和跨平台运行边界 |

## 4. 不补为 P0 的原因

| 能力 | 处理 |
| --- | --- |
| 云端任务委派 | 仍放 P3；没有远端执行环境、账号、安全和审计边界前不做 |
| 插件市场 | 仍放 P3；先做好 skills/hooks/MCP 的本地治理 |
| 完整 Notebook/data IDE | 放 P2；先支持证据记录和命令输出，再补专门 UI |
| 多根 checkpoint 自动合并 | 放 P2；跨 Git root 的回滚风险高，先做显式边界和工作树隔离 |
| 成本精确计费 | 放 P1；先做估算、配额和速率状态，不承诺 Provider 账单完全一致 |

## 5. 后续使用规则

1. 后续任何 DevSeek 功能需求，都必须先映射到 REQ-A~M。
2. 若无法映射，先补本审计文档说明为何它是程序员智能编程体的必要能力。
3. 实施时优先 P0：Plan、工具、权限、质量门禁、历史任务、Provider、忽略规则、冲突处理。
4. P1 再做强：符号索引、环境识别、语言/运行时支持矩阵、CLI 交互、跨平台 adapter、外部文档 grounding、成本预算、记忆 UI、hooks/skills。
5. P2/P3 才做大：多根、worktree、后台、自动化、云端和插件市场。
