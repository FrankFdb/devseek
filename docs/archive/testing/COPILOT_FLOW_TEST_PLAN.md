# Copilot 风格主流程测试计划

目标：验证聊天主区是否只展示任务状态 + 文件清单，代码查看是否进入编辑区，修复流程是否按轮次汇总且去噪。

## 0. 前置

1. 在 `packages/vscode-extension` 执行编译。
2. 在 VS Code 执行 `Developer: Reload Window`。
3. 确认设置：`deepseek.generatedContentDisplayMode=hidden`。

## 1. 生成文件场景（主区不展示整段代码）

测试提示词：

```text
请在 code/dog 下创建一个最小 C++ 继承示例，输出 3 个文件：Animal.h, Dog.h, main.cpp
```

期望结果：

1. 聊天主区出现“正在生成文件清单，代码正文已隐藏”占位提示。
2. 结束后主区显示“检测到 N 个可应用文件/补丁”面板。
3. 主区不出现完整大段源码正文。

失败判定：

1. 生成过程中或结束后出现整段源代码墙。
2. 没有文件路径映射按钮。

## 2. 文件映射点击查看（已落地/虚拟预览）

在上一步结果中：

1. 先点击“预览”（不应用）。
2. 点击某个路径按钮（例如 `code/dog/Animal.h`）。

期望结果：

1. 如果文件未落地，打开虚拟预览编辑器。
2. 如果文件已落地，打开工作区真实文件。
3. 路径包含 `:line` 或 `#L10` 时可跳到对应行。

失败判定：

1. 点击后无反应。
2. 打开了错误目录文件。

## 2.1 单文件对比/替换（Copilot 风格）

在文件映射按钮区：

1. 点击某个文件旁的“对比”。
2. 观察是否仅打开该文件的 diff 预览。
3. 点击同一文件的“替换此文件”。

期望结果：

1. “对比”只影响当前文件，不触发其他文件应用。
2. “替换此文件”只应用当前文件，状态卡与验证信息仍可见。
3. 保留“应用”按钮可执行批量应用。

失败判定：

1. 单文件按钮触发了全量应用。
2. 目标文件与点击项不一致。

## 3. 修复闭环去噪（显示轮次和结果）

测试提示词：

```text
请编译并修复 code/dog 目录代码，直到通过
```

期望结果：

1. 状态卡片以轮次显示，例如“第 1 轮自动修正”。
2. `apply/validate started` 不再刷屏。
3. 同一轮不会重复出现“已收到修正草案（全量覆盖）”多条噪音。
4. 最终有明确结果：通过或失败（达到上限）。

失败判定：

1. 连续出现多条等价状态卡片（无新信息）。
2. 同轮重复修正草案提示。

## 4. 审核主路径验证

目标流程：

1. 看文件列表。
2. 点文件看内容。
3. 看验证结论。

期望结果：

1. 文件列表入口优先且稳定可用。
2. 代码审阅在编辑区进行，不依赖聊天区大段正文。
3. 验证结论以状态卡清晰呈现（通过/失败/跳过）。

补充期望：

1. 聊天主区上方出现临时 Working 区域，动态展示“进行中”步骤。
2. 回复完成后 Working 区域自动收敛/清空，不形成持续刷屏噪音。

## 4.1 修改队列（Keep / Undo）

触发方式：

1. 先执行一次“应用”或“替换此文件”。
2. 观察输入框上方是否出现“文件修改队列”。

期望结果：

1. 每个修改项都显示文件路径与变更计数（`+N -M`）。
2. 队列支持累加，未处理项不会被新一轮覆盖。
3. 单项支持：`查看`、`Keep`、`Undo`。
4. 批量支持：`Keep All`、`Undo All`。
5. `Undo` 后文件应恢复到该修改前状态（新建文件应被删除）。

失败判定：

1. 队列只显示最后一项，历史项丢失。
2. `Undo` 无法恢复原文件。
3. 同一路径多次修改时，按钮操作作用到错误版本。

## 5. 回归检查

1. 普通问答（非生成文件）应正常显示正文。
2. Mermaid/代码块工具栏能力不受影响。
3. `/shell`、`@file`、`#problems` 不回归。

## 6. 记录模板

每次测试记录：

1. 输入提示词
2. 关键截图（主区 + 编辑器）
3. 是否通过
4. 失败时的复现步骤与日志片段
