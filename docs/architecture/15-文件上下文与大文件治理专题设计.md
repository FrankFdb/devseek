# DevSeek 文件上下文与大文件治理专题设计

文档编号：ARCH-15
最后更新：2026-06-30
状态：实施中
关联文档：[05-代码重构实施计划.md](05-代码重构实施计划.md)、[09-程序员工程完整性架构设计.md](09-程序员工程完整性架构设计.md)、[12-Agentic修复运行时专题设计.md](12-Agentic修复运行时专题设计.md)

## 1. 背景

本轮 shape_manager 测试暴露出两类同源问题：

1. `read_file` 对中等大小源码文件做了隐式截断，模型误以为已经读取完整文件，导致只分析不修改。
2. DeepSeek 网页返回 `search_content(...)` 等工具别名时，DevSeek 的解析、执行和前端过滤没有共享同一份工具词典，出现“文字像工具、实际不执行”的情况。

这些问题不能继续靠截图补丁处理，必须升级为文件上下文和工具协议治理专题。

## 2. 对标原则

DevSeek 对标 Claude Code / Codex 的成熟 coding agent 行为，但不假设其内部私有实现：

1. 大文件不应默认整仓、整文件塞进模型，而是通过搜索、目录、符号、范围读取逐步建立工作上下文。
2. 工具返回被截断时，必须明确告诉模型：总行数、返回范围、是否截断、下一步如何继续读取。
3. 模型要修改代码前，必须拿到足够上下文；不能把“部分读取”伪装成“完整读取”。
4. 工具名、工具别名、参数别名、权限分类、执行路径和 UI 展示过滤必须共享同一份规则。
5. 代码生成默认遵守工程规模约束，避免产生超长文件和超长函数；除非用户明确要求单文件交付。

## 3. 文件上下文策略

### 3.1 默认阈值

1. `<=64KB` 且 `<=2000` 行：完整读取，并附带元信息。
2. 超过阈值：默认返回前 `240` 行预览，并标记 `truncated=true`。
3. 范围读取：支持 `startLine/endLine`，单次最多返回 `600` 行。

### 3.2 read_file 输出契约

`read_file` 返回内容必须包含：

1. 请求路径和解析后的路径。
2. 文件字节数和总行数。
3. 本次返回的行范围。
4. `truncated=true|false`。
5. 截断原因。
6. 如果截断，给出继续读取方式。

禁止返回没有元信息的隐式截断内容。

## 4. 工具词典策略

### 4.1 单一事实源

`agent/tool-registry.ts` 是工具能力的单一事实源，负责：

1. canonical tool name。
2. provider/model 输出的工具别名。
3. 参数别名归一。
4. 工具类型、风险、权限模式、活动标签。

`fake-tool-parser`、`tool-call-normalizer`、`tool-executor` 必须从 registry 获取工具规则。

### 4.2 前端镜像守卫

当前 `media/webview.js` 仍有一份前端工具名镜像，用于流式文本清理。必须用单测保证：

1. registry 中所有 canonical 工具名都存在于 webview 镜像。
2. registry 中所有别名都存在于 webview 镜像。
3. 新增工具或别名如果只改后端或只改前端，测试必须失败。

后续目标是把 webview 工具词典改为构建期生成，彻底消除手工镜像。

## 5. 代码规模治理

DevSeek 默认向模型注入工程规模约束：

1. 生产代码文件超过 `1024` 行必须审计职责。
2. 超过 `2048` 行必须制定拆分计划。
3. 超过 `3000` 行必须作为重构优先级。
4. 普通函数控制在 `100` 行以内。
5. 复杂编排函数不得超过 `300` 行。
6. 新功能优先进入小型领域服务、纯函数和可单测模块。
7. 修复问题时要修缺陷类别，审计同类入口；相同逻辑原则上只能有一份。

这些规则必须进入 Agentic loop、Editor loop、Architect planner，而不是只存在于文档。

## 6. 已实施基线

1. 新增 `workspace/file-context-service.ts`，统一 `read_file` 的路径解析、完整读取、范围读取和截断元信息。
2. 两个 Agent `onReadFile` 回调已收敛到 `FileContextService`。
3. `read_file` 支持 `startLine/endLine`。
4. `tool-registry.ts` 新增工具 alias 和参数 alias 归一，`search_content` 归一为 `grep_search`。
5. `fake-tool-parser` 与 `tool-call-normalizer` 已改为使用 registry 规则。
6. `webview.js` 已支持过滤 `search_content`，并由 registry 同步测试守卫。
7. 新增 `agent/engineering-guidelines.ts`，并注入 Agentic loop、Editor loop、Architect planner。

## 7. 后续路线

1. 将 `webview.js` 的工具名镜像改为构建期从 registry 生成。
2. 为 `read_file` 增加符号级 outline 输出，优先按函数/类读取。
3. 对 `extension.ts`、`agent-loop.ts`、`webview.js` 制定分阶段拆分计划。
4. 将代码规模阈值接入静态检查，阻止新增能力继续堆进超长文件。
5. 建立“工具别名样本库”，持续收集 DeepSeek 网页、API、OpenAI-compatible、VS Code LM 的工具输出变体。
