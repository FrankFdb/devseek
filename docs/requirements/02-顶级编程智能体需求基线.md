# DevSeek 顶级编程智能体需求基线

文档编号：REQ-02
最后更新：2026-06-18
状态：后续优化迭代主目标文档
参考对象：Claude Code、OpenAI Codex、GitHub Copilot / Copilot cloud agent / VS Code Copilot；补充参考 Cursor、Devin Desktop / Windsurf Cascade、Cline、Aider、Gemini CLI

## 1. 目标

DevSeek 后续需求目标不是复制任一竞品，而是吸收三类优秀编程智能体中用户价值最高的能力：

1. Claude Code：终端优先、计划模式、权限模式、记忆、hooks、skills、subagents。
2. Codex：`AGENTS.md` 指令链、沙箱与审批、IDE/CLI/App/Cloud 一致体验、Review pane、非交互自动化、插件与 MCP。
3. GitHub Copilot：IDE 原生 Agent/Edit/Inline Chat、工具选择、代码库上下文、云端 issue/PR 工作流、代码审查、自定义 agent/skills。
4. 其他成熟 Agent：任务 checkpoint、repository map、忽略规则、多根工作区、环境识别、成本/配额、Web/Docs Search、可复用 workflows。

DevSeek 的目标形态：

> 一个本地优先、可控可审计、显示与功能分离、能规划、能修改、能验证、能回退、能长期学习项目规则的多入口编程智能体。

## 3. 当前现状摘要

完整现状见 [01-当前需求现状.md](01-当前需求现状.md)。架构重构范围见 [07-架构重构需求澄清.md](07-架构重构需求澄清.md)。核心判断：

| 能力域 | DevSeek 当前 | 目标差距 |
| --- | --- | --- |
| 多文件 Agent | 已具备多轮任务、文件写入、终端执行、自动修复 | 需要更强计划模式、工具协议和权限模型 |
| 上下文 | 有附件、recent files、摘要和项目规则 | 需要统一指令发现链、代码库索引和可解释上下文预算 |
| 代码库导航 | 主要依赖文本搜索和模型判断 | 需要 repository map、符号索引、定义/引用、诊断和多根工作区治理 |
| 模型能力 | 已有 DeepSeek Web Bridge、DeepSeek API、OpenAI compatible 雏形 | 需要明确 DeepSeek Web 默认实现，其他大模型通过 API 直连接入同一 Agent Runtime |
| 记忆体 | 有 session 历史、摘要、recent files、项目规则和 AI 可写记忆 | 需要独立 MemoryService、分层 schema、读写策略、隐私阻断和可管理 UI |
| 变更审查 | 有 File Changes、Keep/Undo | 需要按 hunk / inline comment / Git stage 粒度审查 |
| 验证闭环 | 有编译/执行失败定位和修复范围收敛 | 需要可配置验证策略、hooks 和自动化报告 |
| 扩展能力 | 有 MCP 雏形 | 需要 skills、subagents、插件化工具和权限分层 |
| 历史任务与续作 | 有历史会话、摘要、recent files 和旧版 Agent checkpoint 雏形 | 需要独立任务历史、任务列表、打开续作、恢复证据和幂等保护 |
| 工程环境与依赖 | 已能运行终端和局部验证 | 需要识别语言、包管理器、测试命令、dev server、依赖安装风险和网络审批 |
| 语言与运行时支持 | 主要依赖 VS Code language id、文件后缀和 prompt 中的语言信息 | 需要按语言声明索引、诊断、依赖、格式化、测试、运行和降级能力，形成可验收支持矩阵 |
| 忽略规则与冲突 | 有部分路径保护和回退能力 | 需要 `.devseekignore` / `.gitignore` / generated/vendor/large file 统一排除，以及用户并发修改冲突处理 |
| 成本与配额 | DeepSeek Web 低门槛，API Provider 可接入 | API Provider 需要 token、上下文、费用、速率限制和重试预算可见 |
| 运行形态与界面解耦 | 主要以 VS Code 插件和 WebView 为用户界面，部分业务仍靠 extension/WebView 入口牵引 | 需要 Headless Agent Core + Surface Adapter；VS Code、CLI、桌面/本地 Web、非交互脚本共享同一运行时 |
| 跨平台运行 | VS Code 插件天然覆盖 Windows/Linux/macOS，终端、浏览器桥接、路径和 shell 行为尚未作为独立设计验收 | 需要 Linux/macOS/Windows native 与 WSL 边界、shell adapter、path/case/权限差异和打包更新策略 |
| 后台/自动化 | 暂缺 | 需要先从本地非交互任务与工作树隔离开始 |

## 4. 需求原则

1. **先计划再写盘**：复杂或高风险任务必须支持 read-only planning，用户确认后才编辑。
2. **证据驱动**：Agent 不凭空宣称完成；完成必须绑定文件变更、命令输出、测试结果或明确未验证原因。
3. **最小必要上下文**：默认只读取与任务相关的文件、诊断和命令输出；逐步扩大范围。
4. **权限可解释**：每次写文件、运行命令、访问网络、使用 MCP/外部工具，都能说明原因、范围和风险。
5. **可回退可审查**：所有 AI 变更必须能预览、局部接受、局部撤销、整体撤销。
6. **项目规则持久化**：构建命令、架构边界、编码规范、禁止事项必须自动进入后续会话。
7. **过程不污染主对话**：探索、日志、工具输出进入 Working/子任务/可展开区域，主对话只给用户结论。
8. **优秀能力产品化**：只有能落到 DevSeek 架构和验证闭环里的能力，才能进入 P0/P1。
9. **记忆不替代规则**：长期记忆只能辅助上下文，不能覆盖项目指令、权限模型、hooks 或用户本轮明确要求。
10. **任务历史不等于聊天历史**：聊天记录用于查看对话，任务记录用于恢复执行、审计变更、追踪验证和继续工作。
11. **Provider 可替换但内核不分叉**：DeepSeek Web 是默认模型实现，API 大模型可直连接入，但所有 Provider 必须共享同一工具、权限、验证、历史任务和记忆边界。
12. **真实工程场景优先**：需求必须覆盖程序员日常的理解、修改、运行、调试、测试、审查、提交、续作和回退。
13. **外部事实可追溯**：依赖版本、第三方 API、框架用法、联网资料和模型能力都要能说明来源，不能只靠模型记忆。
14. **显示与功能分离**：VS Code、CLI、桌面/本地 Web 和非交互脚本只能是不同 Surface；计划、权限、工具、Provider、历史任务、记忆和验证必须在共享 Agent Core 中完成。
15. **先需求后重构**：后续优化先确认编号需求，再制定重构设计计划、重构代码计划和重构测试计划。

| ID | 需求 | 对标 | 优先级 | 验收标准 |
| --- | --- | --- | --- | --- |
| REQ-J1 | DeepSeek Web 输出必须经过独立质量门禁后才用于最终交付 | Codex test/review loop / Copilot iterative fixes / Claude verify hooks | P0 | 代码生成结果至少经过语法/静态检查、相关测试或可解释的验证跳过；失败时进入修复或等待用户确认 |
| REQ-J2 | 文件变更应用前后都要可审计、自检查、可回退 | Codex review pane / Claude checkpointing / Copilot file changes | P0 | 每个 change set 有来源、diff、快照、验证结果和最终使用结论 |
| REQ-J3 | DeepSeek Web 回复不稳定时可恢复当前编程任务 | Claude resume sessions / Codex resume and session log / Copilot agent session | P0 | 浏览器刷新、桥接断线、输出截断后，能基于 TaskCheckpoint 继续计划、工具结果和未完成步骤 |
| REQ-J4 | Provider 输出要有完整性检测和幂等重放保护 | Codex sandbox/review / Claude tool permissions | P1 | 重试不会重复执行已成功的写盘/终端副作用；截断响应不会被当作完成 |
| REQ-J5 | 支持独立 reviewer/verifier 子流程 | Claude subagents / Codex `/review` / Copilot code review | P1 | 关键变更可由只读 reviewer 或 QualityGate 二次检查，检查结果进入 ReviewLedger |

### REQ-K：历史任务与续作

历史任务不是普通聊天收藏。它必须保存 Agent 完成真实编程任务所需的执行事实，让用户关闭 VS Code、切换历史任务或 Provider 恢复后，仍能继续当前工作。

| ID | 需求 | 对标 | 优先级 | 验收标准 |
| --- | --- | --- | --- | --- |
| REQ-K1 | 保存结构化历史任务记录 `TaskRunRecord` | Claude resume sessions / Codex session log / Copilot agent session | P0 | 每个 Agent 任务保存目标、workflow 状态、批准计划、todo、涉及文件、工具结果、change set、验证结果、QualityGate、失败/暂停原因 |
| REQ-K2 | 历史任务列表与详情查看 | Claude sessions / Codex app tasks / Copilot agent history | P1 | 用户能按状态、时间、仓库、文件、Provider 查看历史任务，并看到计划、变更、验证、未完成项和风险 |
| REQ-K3 | 打开历史任务后继续工作 | Claude resume / Codex resume | P0 | 打开任务后可基于上次稳定 checkpoint 继续，不要求用户重新描述目标；恢复上下文只注入必要事实 |
| REQ-K4 | 任务续作必须幂等且可审计 | Codex review/sandbox / Claude permissions | P0 | 已提交的写盘、终端、MCP、记忆写入不会因继续任务重复执行；所有重放决策进入审计事件 |
| REQ-K5 | 历史任务与会话、记忆体分层互通 | Claude memory / Codex memories / Copilot Memory | P1 | `SessionService` 负责对话显示，`TaskHistoryStore` 负责任务事实，`MemoryService` 只吸收可复用摘要和经验 |
| REQ-K6 | 历史任务隐私、清理和导出 | Codex session privacy / Copilot workspace trust | P1 | 用户能删除、归档、导出任务记录；敏感输出只保存脱敏摘要，不能把 token、cookie、私钥写入任务历史 |

### REQ-L：模型供应商与大模型能力接入

DevSeek 默认使用 DeepSeek 网页版作为低门槛模型实现，同时允许 DeepSeek API、OpenAI compatible、本地模型、企业私有模型等通过 API 方式直接接入。Provider 只能提供模型能力，不能绕过 Agent Runtime。

| ID | 需求 | 对标 | 优先级 | 验收标准 |
| --- | --- | --- | --- | --- |
| REQ-L1 | DeepSeek Web Bridge 作为默认 Provider | DevSeek 当前优势 / Claude Code 低门槛本地入口 | P0 | 新用户默认可通过 DeepSeek 网页路径使用；登录、健康状态、异常恢复和质量门禁可见 |
| REQ-L2 | 支持 API Provider 直接接入其他大模型 | Codex model surfaces / Copilot 多模型 / OpenAI compatible | P0 | DeepSeek API、OpenAI compatible、本地或企业 API 可配置 base url、api key、model，并走统一 `LLMProvider` |
| REQ-L3 | Provider 能力契约与降级 | Codex provider abstraction / VS Code LM | P0 | 每个 Provider 声明 streaming、system prompt、native tool calling、structured output、vision、max tokens、resumable session 等能力 |
| REQ-L4 | Provider 选择、健康检查和 fallback | Copilot model picker / Codex provider health | P1 | UI 显示当前 Provider、模型、可用状态；Provider 不可用时可切换或降级，且不重复执行副作用 |
| REQ-L5 | Provider 输出统一进入工具协议和质量门禁 | Claude/Codex/Copilot tool governance | P0 | DeepSeek Web 文本工具、API native tool calling、structured output 都必须规范化为 `LLMEvent`/`ToolCall` 后再执行 |
| REQ-L6 | Provider 安全与隐私隔离 | Codex sandbox/security | P1 | API key 不进入 prompt、历史任务、记忆或日志；Provider 不能直接读写 workspace 或执行终端 |

### REQ-M：程序员工程完整性与高频工作流

本节是对 Claude Code / Codex / Copilot 之外成熟编程 Agent 的补充审计。目标是确保 DevSeek 不只会“改文件”，还覆盖程序员真实日常：搭环境、理解代码库、查当前文档、跑服务、看 UI、处理依赖、控制成本、复盘质量。

| ID | 需求 | 对标 | 优先级 | 验收标准 |
| --- | --- | --- | --- | --- |
| REQ-M1 | 工程环境与工具链识别 | Cascade tool/package detection / Aider linting/testing | P1 | 自动识别语言、包管理器、虚拟环境、devcontainer、build/test/lint/run 命令，并写入可审计 `EnvironmentProfile` |
| REQ-M2 | 依赖安装、升级和网络副作用治理 | Claude/Codex permissions / Cascade package install | P1 | 安装、升级、迁移依赖前展示命令、网络访问、lockfile 影响和回退方式 |
| REQ-M3 | 运行预览和可视化验证 | Codex browser use / Cline IDE workflows / Gemini Code Assist IDE agent | P2 | Web/GUI 任务可启动 dev server、打开预览、截图或运行 Playwright；Notebook/data 任务可保存输出证据 |
| REQ-M4 | 当前官方文档与依赖版本 grounding | Cascade Web Search / Aider web pages / Copilot MCP | P1 | 涉及外部 API、框架、CLI、云服务时，优先读取本地 lockfile/package 版本；必要联网时只引用可信来源并附来源摘要 |
| REQ-M5 | Token、上下文、费用和速率预算 | Cline task costs / Copilot budgets / Aider prompt caching | P1 | API Provider 显示 token/上下文/费用估算、限流状态、重试次数和缓存命中；超预算前要求用户确认 |
| REQ-M6 | Agent 任务回放与质量评测 | Aider leaderboards / Codex eval mindset | P2 | 可把历史任务沉淀为 regression case，回放同一需求验证计划、工具、diff、测试和最终质量 |
| REQ-M7 | Issue、PR、TODO、设计文档入口 | Copilot cloud agent / Gemini CLI GitHub Actions | P2 | 用户能从 issue/PR/TODO/设计文档生成任务，保留来源、验收标准和后续评论处理 |
| REQ-M8 | 语言与运行时支持矩阵 | Claude/Codex/Copilot 语言无关 Agent + Aider/Cline/Cascade 工程检测 | P1 | 每种语言/运行时声明可支持的索引、诊断、格式化、构建、测试、运行、依赖管理、文档 grounding 和降级策略 |

语言支持不是一次性承诺“所有语言都同等强”。DevSeek 采用能力分级：

1. **P0 基础语言与工程文件**：优先保障 DevSeek 自身和通用工程文件，包括 TypeScript/JavaScript/Node.js、Markdown、JSON、YAML、Shell、HTML、CSS。
2. **P1 主流工程语言**：Python、Java/Kotlin、Go、Rust、C/C++、C#、PHP、Ruby、SQL 等，需要在仓库存在工具链证据时识别 build/test/lint/run/package profiles。
3. **P2 领域语言和专用环境**：Swift/Objective-C、Dart/Flutter、R、Scala、Elixir、Lua、Jupyter/Notebook 等，先保证上下文、编辑、证据记录，再逐步补齐测试和预览。
4. **未知或弱支持语言**：允许文本级理解和编辑，但必须标记能力不足；不得自动执行高风险命令或宣称已完成语言专属验证。

### REQ-N：运行形态、界面解耦与跨平台

详细审计见 [09-运行形态与界面解耦需求.md](09-运行形态与界面解耦需求.md)。DevSeek 不能把 Agent 能力绑定在 VS Code WebView 里；VS Code 插件只是首个产品入口，CLI、桌面/本地 Web、非交互脚本必须共享同一个 Agent Core。

| ID | 需求 | 对标 | 优先级 | 验收标准 |
| --- | --- | --- | --- | --- |
| REQ-N1 | Headless Agent Core | Claude Code CLI/VS Code/Desktop、Codex CLI/IDE/App、Copilot CLI/IDE/cloud | P0 | Plan、权限、工具、Provider、历史任务、记忆、验证和回退都在 UI 无关内核中执行 |
| REQ-N2 | Surface Adapter 协议 | Codex 多 surface 配置共享 / Copilot 多入口 session | P0 | VS Code WebView、CLI TUI、非交互 JSONL、桌面/本地 Web 都通过统一 `AgentEvent` / `AgentCommand` 协议通信 |
| REQ-N3 | VS Code 插件作为 P0 首发入口 | Copilot IDE / Claude VS Code / Codex IDE | P0 | 保留 File Changes、Inline Chat、Problems/Terminal/Selection 入口和 VS Code 原生命令体验 |
| REQ-N4 | CLI 交互模式 | Claude Code terminal-first / Codex CLI / Copilot CLI | P1 | 支持 `devseek` 进入交互会话、Plan/Edit/Run 模式、权限提示、diff 预览、任务恢复和历史查看 |
| REQ-N5 | CLI 非交互与脚本模式 | Claude `-p` / Codex exec JSON / Copilot programmatic CLI | P2 | 支持单 prompt 执行、只读摘要、受控写盘、JSONL 事件、退出码和 CI/脚本集成 |
| REQ-N6 | 非 VS Code 图形界面 | Claude Desktop / Codex app | P2 | 支持本地 Desktop 或 localhost Web UI 查看任务、diff、历史、Provider、预览和配置，不依赖 VS Code API |
| REQ-N7 | 跨平台运行边界 | Claude/Codex/Copilot Windows、Linux、macOS 支持 | P1 | Linux/macOS shell、Windows PowerShell/CMD/Git Bash/WSL、路径分隔符、大小写、换行、文件锁和权限差异都有 adapter 与测试 |
| REQ-N8 | 共享配置、状态和证据 | Codex CLI/IDE 配置共享 / Claude session resume | P1 | 用户配置、项目配置、历史任务、记忆、checkpoint、Provider 配置在不同 Surface 下可一致读取并受隐私策略约束 |
| REQ-N9 | Surface 能力降级 | 多入口产品共同经验 | P1 | 某 Surface 缺少能力时必须显式降级，例如 CLI 无 hunk UI 时输出 patch 文件或选择菜单，桌面无 VS Code diagnostics 时使用语言服务/命令替代 |
| REQ-N10 | 跨平台打包、安装、更新和诊断 | Claude/Codex setup/doctor | P2 | 每个发布形态有安装、升级、doctor、自检和日志目录规范；错误信息包含 OS、shell、cwd、Provider、权限模式 |
| REQ-N11 | 多目标构建与发布矩阵 | Codex CLI/IDE/App / Claude CLI/VS Code/Desktop | P1 | VS Code VSIX、Bridge、Shared/Core、CLI TUI、CLI JSONL、未来 Desktop/local Web 都有明确 build、watch、test、package、release profile |

## 6. 优先级路线图

### P0：把 Agent 做稳

1. Plan Mode。
2. 结构化工具协议。
3. 权限模式与写入边界。
4. 项目指令发现链。
5. File Changes hunk 级审查。
6. Todo 和最终摘要以执行事实为准。
7. DeepSeek Web 输出质量门禁。
8. Web Bridge 不稳定后的任务恢复。
9. 历史任务保存和打开后续作。
10. DeepSeek Web 默认 Provider 和 API Provider 统一运行时。
11. 内容排除、敏感路径阻断和并发冲突处理。
12. Headless Agent Core 与 Surface Adapter 协议，阻止业务继续绑定 WebView/extension。

### P1：把 Agent 做强

1. 语义代码库索引。
2. Skills 与内置 debug/review/verify 流程。
3. Hooks 生命周期。
4. 记忆体分层、受控写入和可管理 UI（详见 [06-记忆体需求.md](06-记忆体需求.md)）。
5. Git/PR 审查闭环。
6. Inline Chat 和更好的 @ context。
7. Provider 输出完整性检测和 reviewer/verifier 子流程。
8. 历史任务列表、详情、清理和导出。
9. Provider 选择、健康检查、fallback 和多模型能力配置。
10. 符号级 repository map、工程环境识别、语言/运行时支持矩阵、外部文档 grounding、成本/配额预算。
11. CLI 交互模式、跨平台 shell/path adapter、共享配置与状态。

### P2：把 Agent 做大

1. Subagents。
2. Worktree 隔离。
3. CLI 非交互 / JSONL 输出。
4. 非 VS Code 桌面或本地 Web UI。
5. 后台任务列表。
6. PR comment follow-up。
7. 多根工作区、运行预览、Notebook/data workflow、Agent 任务回放评测。

### P3：远期能力

1. 云端任务委派。
2. 插件市场/团队共享包。
3. 自动化调度。
4. 跨仓库任务。

## 7. 后续重构推进方式

后续 DevSeek 优化只按编号需求制定计划，不直接跳过需求进入代码：

| 阶段 | 输出 | 要求 |
| --- | --- | --- |
| 需求确认 | 本轮覆盖的 REQ / MEM 编号、用户目标、非目标 | 需求未确认前不改代码 |
| 重构设计计划 | 模块边界、数据流、权限模型、回退策略、验收标准 | 先解决架构边界，再拆代码；设计文档进入 `docs/architecture/` |
| 重构代码计划 | 修改文件、迁移顺序、兼容策略、灰度路径 | 每一步都能独立验证和回退；计划见 `docs/architecture/05-代码重构实施计划.md` |
| 重构测试计划 | unit、integration、回归、安全、手工验收 | 测试计划必须覆盖主链路和失败/取消/回退链路 |

## 8. 验收标准模板

任何新需求进入实现前，必须在变更闸门中补齐：

| 项 | 要求 |
| --- | --- |
| 用户目标 | 用户完成什么工作更快、更稳或更安全 |
| 对标来源 | Claude Code / Codex / Copilot 中的哪类能力 |
| DevSeek 范围 | 本次实现什么，不实现什么 |
| 权限影响 | 是否写盘、运行命令、访问网络、调用 MCP、读外部数据 |
| 主链路验证 | 至少一条真实用户路径 |
| 回退验证 | 取消、失败、误改、验证失败时如何恢复 |
| 文档更新 | 同步更新需求、设计、变更日志和闸门 |

## 9. 不做范围

1. 不承诺完整复制 Copilot cloud agent 的 GitHub 云端商业流程。
2. 不在没有沙箱和权限模型前提供“无确认全权限自动驾驶”。
3. 不把记忆当强制规则；强制规则必须进入项目指令或 hooks。
4. 不为了竞品对齐引入无法验证的 UI 装饰能力。
5. 不把大型日志、搜索结果或工具输出直接塞入主对话。

## 10. 更新规则

1. 新增需求先进入本文件对应 REQ 编号，再拆到路线图。
2. 若竞品参考更新，只更新 [references/](references/) 和本文件中受影响的需求。
3. 已完成需求不删除，状态应迁移到 [04-Agent优化路线图.md](04-Agent优化路线图.md) 或变更日志。
4. 不再维护独立的无编号竞品清单。
