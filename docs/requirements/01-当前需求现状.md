## 2. 当前产品定位

DevSeek 当前实现仍然以 VS Code 插件为主入口，默认使用 DeepSeek 网页版作为低门槛模型实现，同时允许 DeepSeek API、OpenAI-compatible、本地模型、企业私有模型等通过 API Provider 直接接入。后续目标需要升级为多入口、本地优先、显示与功能分离的编程智能体：VS Code 是 P0 首发入口，CLI、非交互脚本和非 VS Code 图形界面通过同一 Agent Core 逐步实现。

需求边界应避免“完整复刻某一家产品”。后续需求只吸收 Claude Code、Codex、GitHub Copilot 中对用户使用价值最高、且能落到 DevSeek 架构里的能力。

## 5. 近期需求治理原则

1. `02-顶级编程智能体需求基线.md` 是后续需求收口入口。
2. 新需求必须明确来源、用户价值、验收标准和不做范围。
3. 已实现能力只保留必要状态，不继续堆历史日志；历史过程移入归档。
4. 和安全、写盘、终端、网络、Git 相关的能力，必须先补权限模型和回退策略。
5. 对标竞品时优先吸收“工作方式”和“用户体验”，不照搬命名、订阅形态或云端商业能力。

## 6. 后续重构推进方式

后续 DevSeek 优化不直接跳到代码实现。每次重构先从编号需求确认开始，再制定计划：

1. **需求确认**：先确认本轮覆盖 `02` 总基线中的哪些 REQ 编号，以及是否涉及 [06-记忆体需求.md](06-记忆体需求.md) 中的 MEM 编号。
2. **重构设计计划**：只规划模块边界、数据流、权限边界、回退策略和验收标准。
3. **重构代码计划**：在设计计划确认后，再拆实现步骤、影响文件、迁移顺序和兼容策略。
4. **重构测试计划**：最后补单元测试、集成测试、回归路径、安全/隐私验证和手工验收路径。
5. **执行约束**：需求未确认前不改代码；设计、代码、测试计划未闭环前不进入大规模重构。
