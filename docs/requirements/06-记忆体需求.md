# DevSeek 记忆体需求

文档编号：REQ-06
最后更新：2026-06-18
状态：记忆体重构前的需求基线
用途：定义 DevSeek 记忆体的边界、分层、读写规则、验收标准和后续重构推进方式。

对应设计：[../architecture/04-记忆体架构设计.md](../architecture/04-记忆体架构设计.md)

## 1. 目标

DevSeek 记忆体的目标不是让 Agent “什么都记住”，而是让它在安全、可控、可查看、可删除的前提下，稳定复用对用户真正有价值的信息：

1. 记住项目规则、构建方式、测试方式和架构边界。
2. 记住用户长期偏好和常用工作方式。
3. 记住已经验证过的修复经验、命令经验和项目事实。
4. 避免重复扫描、重复询问、重复踩坑。
5. 在每次使用记忆时说明来源，允许用户管理和关闭。

记忆体必须服务 DevSeek 的核心目标：本地优先、可控可审计、能规划、能修改、能验证、能回退。

## 2. 对标结论

| 对标对象 | 可吸收做法 | DevSeek 要求 |
| --- | --- | --- |
| Claude Code | `CLAUDE.md` 放强规则，auto memory 记录偏好、命令和调试经验 | 强规则与经验记忆分离，不能把强制规则只放进自动记忆 |
| OpenAI Codex | `AGENTS.md` 作为项目指令链，memory 记录偏好和工作方式 | 项目规则优先级高于记忆；更近目录规则覆盖上层规则 |
| GitHub Copilot | custom instructions、memory、skills 分工明确 | 简单常驻规则进入 instructions，复杂流程进入 skills，重复经验进入 memory |

DevSeek 不复制某一家产品的命名或云端形态，只吸收“规则可追溯、经验可复用、记忆可治理”的工作方式。

## 3. 当前问题

| 问题 | 影响 |
| --- | --- |
| 会话历史、摘要、recent files、项目规则和 AI 可写记忆边界不清 | Agent 容易混用临时上下文和长期事实 |
| 记忆缺少统一 schema 和来源记录 | 后续无法解释“为什么这条信息进入 prompt” |
| 记忆写入策略不明确 | 可能保存临时结论、错误经验或敏感信息 |
| 项目规则和自动记忆优先级不明确 | 记忆可能覆盖更可靠的项目文档 |
| 用户缺少查看、禁用、删除、合并入口 | 记忆会变成不可见状态，降低信任 |
| 记忆没有 TTL、置信度和验证状态 | 老旧构建命令、旧架构事实可能长期污染上下文 |

## 4. 记忆体边界

| 类型 | 说明 | 生命周期 | 是否可自动写入 |
| --- | --- | --- | --- |
| M0 会话记忆 | 当前会话的计划、决策、编辑文件、验证结果 | 当前会话 | 是 |
| M1 任务摘要记忆 | 一次任务结束后的摘要、变更文件、验证结果、未完成事项 | 工作区级，可过期 | 是，但需带来源 |
| M2 项目规则记忆 | 构建命令、测试命令、架构原则、禁止事项、DoD | 项目级，来自文件 | 否，只能由规则文件或用户编辑 |
| M3 项目经验记忆 | 已验证的修复经验、常见坑、模块职责、命令经验 | 工作区级，可过期 | 低风险可建议写入，高影响需确认 |
| M4 用户偏好记忆 | 语言、输出风格、审批偏好、常用流程 | 用户级 | 需用户授权或明确偏好表达 |
| M5 工具与验证记忆 | 命令成功/失败记录、测试耗时、常用验证路径 | 工作区级，短 TTL | 是 |
| M6 禁止记忆 | token、密钥、隐私数据、临时日志、大段源码 | 不保存 | 禁止 |

## 5. 核心需求

| ID | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| MEM-01 | 建立统一 MemoryService，管理读、写、更新、删除、检索 | P0 | 代码中不再散落多套长期记忆写入逻辑 |
| MEM-02 | 记忆 schema 必须包含 `id`、`type`、`scope`、`content`、`source`、`confidence`、`createdAt`、`updatedAt`、`ttl`、`lastUsedAt`、`status`、`tags` | P0 | 任一记忆都能追溯来源、范围和有效性 |
| MEM-03 | 记忆分 scope：session、workspace、repository、user | P0 | 不同仓库的项目经验不会互相污染 |
| MEM-04 | 读取记忆时按优先级组装：项目规则 > 当前任务事实 > 用户显式偏好 > 已验证经验 > 普通历史摘要 | P0 | prompt 中能展示或记录本轮加载了哪些记忆 |
| MEM-05 | 自动写入只允许低风险事实；项目规则、用户级偏好和高影响经验需要用户确认 | P0 | Agent 不能静默写入长期强规则或用户级偏好 |
| MEM-06 | 记忆不能授权写盘、运行命令、访问网络或调用 MCP | P0 | 权限仍由权限模型和用户确认决定 |
| MEM-07 | 敏感信息检测与阻断 | P0 | 疑似 token、secret、私钥、密码、cookie 不进入长期记忆 |
| MEM-08 | 记忆冲突解决 | P1 | 同一命令或规则出现冲突时，优先使用来源更可靠、更新时间更近、用户确认过的信息 |
| MEM-09 | 记忆过期与降权 | P1 | 超过 TTL 或多次验证失败的记忆自动降权，不再默认注入 |
| MEM-10 | 记忆管理 UI | P1 | 用户可以查看、搜索、禁用、删除、编辑、固定记忆 |
| MEM-11 | 记忆写入反馈 | P1 | Agent 建议保存记忆时说明原因、范围和内容，用户可接受或拒绝 |
| MEM-12 | 与 Plan Mode 集成 | P1 | Plan 阶段只读记忆并展示依据，批准前不写入长期记忆 |
| MEM-13 | 与 Skills / Hooks 集成 | P2 | skill 可声明需要读取的记忆类型，hook 可阻断敏感记忆写入 |
| MEM-14 | 非交互模式记忆策略 | P2 | CI/脚本模式默认不写用户级长期记忆，除非显式配置 |

## 6. Prompt 注入规则

1. 记忆只能以摘要形式注入，不把大量历史日志或大段源码直接塞入主 prompt。
2. 每条注入记忆必须保留来源和 scope，便于 debug 与用户审查。
3. 当前任务事实优先于旧记忆；命令最新执行结果优先于历史成功经验。
4. 当记忆与项目规则冲突时，项目规则胜出，并提示用户存在冲突。
5. 当记忆置信度低或已过期时，只能作为候选线索，不得作为最终事实。
6. 记忆不得覆盖用户本轮明确指令。

## 7. 存储与隐私要求

| 要求 | 说明 |
| --- | --- |
| 本地优先 | 默认存储在本地 VS Code workspace/global storage，不做云同步 |
| 可关闭 | 用户可关闭自动记忆写入，也可关闭记忆读取 |
| 可导出 | 支持导出为 Markdown 或 JSON，便于审查和备份 |
| 可清理 | 支持按 scope、类型、时间、项目清理 |
| 可审计 | 关键写入、删除和冲突处理要有轻量日志 |
| 不保存敏感数据 | 命中敏感模式时直接拒绝保存或要求用户手动确认脱敏版本 |

## 8. 与现有 DevSeek 能力的关系

| 现有能力 | 记忆体改造方向 |
| --- | --- |
| sessionHistory | 保留为 M0 会话记忆，不直接升级为长期事实 |
| 会话摘要 | 转为 M1 任务摘要记忆，附带文件、命令、验证结果和未完成项 |
| 历史任务 | 进入 `TaskHistoryStore`，保存任务事实、checkpoint、change set、验证和 QualityGate；只把可复用摘要提炼为记忆 |
| recent files | 作为当前任务上下文线索，不自动成为长期项目事实 |
| `.deepseek/rules.md` / 项目规则 | 升级为 M2 项目规则记忆来源，优先级高于自动记忆 |
| AI 可写记忆 | 收口到 MemoryService，受 schema、权限、敏感信息检测和用户管理约束 |
| MCP / tools | 可读取必要记忆，但不能绕过权限模型写入或执行 |

## 9. 验收用例

| 场景 | 预期 |
| --- | --- |
| 用户明确说“以后回答都用中文” | 写入 M4 用户偏好，后续会话生效，可在 UI 中删除 |
| Agent 连续两次验证 `npm test --workspace=packages/vscode-extension` 成功 | 可建议保存为 M5 验证记忆，带来源和时间 |
| `.devseek/rules.md` 与旧记忆冲突 | 使用规则文件，提示旧记忆已降权 |
| 命令曾经成功但本轮失败 | 本轮失败结果优先，旧成功经验降权 |
| prompt 或输出中出现 token/secret | 不写入长期记忆，并提示已阻断 |
| 用户关闭记忆读取 | prompt 不注入长期记忆，只保留当前会话上下文 |
| 用户删除某条记忆 | 后续任务不再使用该记忆，删除操作可审计 |

## 10. 后续重构推进方式

后续不直接跳到代码实现。每次推进记忆体能力时，按以下顺序制定计划并执行：

1. **需求确认计划**：确认本轮覆盖哪些 MEM 编号、用户价值、非目标和验收用例。
2. **重构设计计划**：梳理现有 session、summary、recent files、rules、AI memory 的数据流，设计 MemoryService 边界、schema、存储位置、迁移策略和权限策略。
3. **重构代码计划**：按最小闭环拆分实现顺序，先收口写入和读取，再接入 prompt 组装、UI 管理、敏感信息阻断和 hooks。
4. **重构测试计划**：覆盖 unit、integration、回归、安全与隐私测试，尤其验证记忆隔离、冲突降权、删除后不再注入和敏感信息阻断。
5. **执行与回退计划**：每一阶段都必须能回退到旧 session/history 逻辑，不能阻断基本聊天和 Agent 修复链路。

## 11. 不做范围

1. 暂不做云端记忆同步。
2. 暂不引入向量数据库作为第一阶段依赖。
3. 暂不做跨仓库自动共享记忆。
4. 暂不允许模型静默改写项目强规则。
5. 暂不把记忆作为权限依据。
