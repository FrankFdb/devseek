# DevSeek 工程完整性与顶级增强需求

文档编号：REQ-10
最后更新：2026-06-21
状态：Phase 11/12 活跃需求

## 1. 背景

Phase 10 已把 DevSeek 从单一 VS Code 插件推进到 Headless Agent Core + Surface Adapter 的多入口方向。Phase 11/12 的目标不是继续增加入口层分支，而是把优秀编程智能体必须具备的工程事实、上下文安全、运行时识别、hooks、skills、subagents、MCP 和 Git/PR 辅助抽到共享内核。

对标 Claude Code/Codex，DevSeek 后续能力必须满足：

1. 在任何 surface 中都先理解工程环境，再进入编辑和验证。
2. 忽略规则、敏感文件、依赖安装、网络访问、冲突检测和预算提示是 Agent Core 边界，不是 UI 组件逻辑。
3. Hooks/skills/subagents/MCP 必须通过可审计契约接入权限、证据和 QualityGate。
4. 自动测试使用确定性本地回归；真实 DeepSeek Web/VS Code UI 使用集成冒烟和手动测试补充。

## 2. Phase 11 需求

| 编号 | 需求 | 验收 |
| --- | --- | --- |
| P11-R1 | 构建统一 `EngineeringContextService` | 输入 workspace 文件候选后输出 visible/excluded、repo index、environment、runtime、budget |
| P11-R2 | 合并 `.devseekignore`、`.gitignore`、默认 generated/vendor、用户排除和敏感路径策略 | 被排除内容不能进入 prompt、记忆或写盘候选 |
| P11-R3 | 识别语言和运行时能力 | TypeScript/JavaScript、Python、Go、Rust、C/C++、unknown 均有明确 profile 和降级说明 |
| P11-R4 | 识别构建、测试、lint、run 命令 | 从 manifest 和项目文件推导命令，不靠模型猜测 |
| P11-R5 | 依赖安装和网络副作用必须先分类 | npm/pnpm/yarn/pip/cargo/go/curl/wget 等命令进入 approval |
| P11-R6 | 写盘前冲突检测 | hash、mtime、dirty editor 任一变化都不能静默覆盖 |
| P11-R7 | 外部文档 grounding 必须声明联网原因和允许来源 | 当前文档需求不能被伪造为本地事实 |
| P11-R8 | 预算与 replay case 可追溯 | 上下文规模、估算 token、历史 case 事件序列可记录 |

## 3. Phase 12 需求

| 编号 | 需求 | 验收 |
| --- | --- | --- |
| P12-R1 | Hooks 通过策略计划执行 | beforeEdit/afterEdit/beforeValidate/afterValidate 均有契约，敏感文件写入被阻断或审批 |
| P12-R2 | Skills 以 `SKILL.md` 渐进发现 | 只能按触发词和任务需要加载，不能一次性污染上下文 |
| P12-R3 | Subagents 是可审计契约 | reviewer/test-writer/diagnostics/migration-planner 有输入输出契约和审批边界 |
| P12-R4 | MCP 工具继承权限域 | read/write/network/destructive 映射到 inspect/edit/network/destructive permission |
| P12-R5 | Git/PR 辅助基于证据 | commit/PR 摘要必须引用 changed files、validation 和风险 |

## 4. 测试策略

1. Shared core 使用纯单元测试验证确定性策略。
2. CLI Bridge 使用本地假 Bridge 测协议、SSE 和等待提示，避免真实网页不稳定影响回归。
3. 真实 DeepSeek Web 只作为集成冒烟：验证登录态、Bridge 连接和网页可用性。
4. VS Code WebView 交互、按钮位置、File Changes、Todos、QualityGate 展示继续使用手动测试 case。
