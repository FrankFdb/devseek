## 6. CLOSE 通过后的任务领取

整个 CLOSE 工作包通过后，只按 [14 第 3 节](14-未完成事项与后续整体迭代计划.md#3-gpt-55-原子任务总队列) 领取前置全部 `PASS` 且明确 claimable 的一个 leaf。顺序起点：

```text
CLOSE-01 active runtime identity
→ CLOSE-02 same-window receipt
→ G0-01 Active Baseline selector
→ G0-02 legacy inventory
→ G0-03 generated banners/status
→ G0-04..12 repository governance/wiring
→ EXT-01..05 required authority receipts
→ G0-13 protected execution
→ G0-14 machine decision
→ machine PASS only: R1-A leaf chain
```

规则：

1. 前一项未 `PASS` 不领取下一项；`BLOCKED` 就停止等待 authority/用户，不找旁路。
2. 一窗口只认领一个 claimable leaf；WIP=1。子代理只读复审或跑无写冲突验证，不能各自提交。
3. 发现 sibling defect class 时在当前 authority 内审计；需要第二 authority 就登记新 leaf，不顺手实现。
4. repository blocker 只有 reachability/checker 证据才能下降；external blocker 只能由外部 authority receipt 关闭。
5. machine Gate 0 明确 `PASS` 前不得修改 R1。

`G0-01` 的完整 card 在 14 §3.2；它不是当前首卡，禁止从旧版本文复制后直接实施。

## 7. 固定 GPT-5.5 微循环

1. 读取作业卡、机器事实和 baseline/dirty；区分 repository fact、test evidence、inference、proposal。
2. 补齐 14 §5 所有字段，构造最小失败或攻击反例并记录 first failure。
3. 修改唯一 semantic authority；审计 sibling entrypoint/state/protocol/persistence/recovery/UI。
4. 删除旧 owner 或留下有删除门的无语义 delegator；添加静态 bypass guard。
5. focused → affected package → replay/headless → architecture/generated drift。
6. 独立对抗复审 P0=0/P1=0。
7. Phase 0～12；只在事实改变时同步批准的 machine SSOT/14/15，17 作为批次检查点不滚动改写。
8. staged boundary/diff review，一个 task/source commit；从 clean commit 重跑 Phase。
9. Extension/Bridge 行为改变时才 compile/package/Bridge/hash/install；按 applicability 分开 artifact 与 handoff commit。
10. 以 `PASS|BLOCKED|FAIL` 结算当前 leaf 并停止，不自动进入下一卡。

早层失败不得跳后层。后续成功不能覆盖首个失败；解除 adverse state 必须显示新的 committed effect、matching verification 和 recovery 因果链。

## 8. 权限与外部动作

以下动作必须在**当前窗口、当前 task/candidate、明确 action/scope、有效期**上重新取得授权或 authority，永不从旧聊天/旧窗口继承：

- push、PR、marketplace 发布或共享基础设施变更；
