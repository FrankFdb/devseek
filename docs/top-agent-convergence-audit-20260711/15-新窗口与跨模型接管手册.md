## 7. 固定工程作业顺序

每个 GPT-5.5 任务使用同一微循环：

1. 读取作业卡、机器 SSOT、baseline/dirty；区分 fact/evidence/inference/proposal。
2. 构造一个最小失败或攻击反例；记录 first failure。
3. 修改唯一 semantic authority，审计 sibling entrypoint/state/protocol/persistence/recovery/UI。
4. 删除旧 owner 或留下有删除门的无语义 delegator；添加静态 bypass guard。
5. focused→affected package→replay/headless→architecture/generated drift。
6. 独立对抗复审，P0=0/P1=0。
7. Phase 0～12；同步 machine SSOT 与 14/15/17 的事实，不通过 Markdown 提升状态。
8. staged boundary/diff review，一个 commit；从 clean commit 重跑 Phase。
9. Extension/Bridge 行为改变时 package/Bridge/hash/install/identity；需要 Surface 证据时使用用户当前 DevSeek 窗口。
10. 以 `PASS|BLOCKED|FAIL` 结算并停止，等待用户或下一窗口。

早层失败不得跳后层“看看是否能过”。后续成功不能覆盖首个失败；修复后必须显示新的 committed effect、matching verification 和 recovery 因果链。

## 9. 异常处理

| 异常 | GPT-5.5 必须做 | 禁止做 |
| --- | --- | --- |
| dirty 与回执不同 | 定向读取 diff、辨认用户/任务边界 | reset/clean/stash/覆盖 |
| focused/full 失败 | 保存首个根因，回唯一 authority | 弱化 oracle、skip、标 flaky 后继续 |
| Phase 失败 | 不提交/不打包，按失败 gate 回 focused | 用旧报告或别的 commit 顶替 |
| package/install identity 不同 | 停止，从精确 commit 重建 | 混用旧 VSIX、改文档假装相同 |
| 同窗口 UI 无法自动化 | 记录具体环境 blocker，请用户完成最小 manual gate或恢复辅助能力 | 另开隔离窗口并称同窗口通过 |
| 文档与 machine SSOT 冲突 | machine actual evidence 优先，登记 superseding fact | Markdown 改 claim/state |
| external authority 缺失 | `blocked-by-external-authority` 并停止 | 本地 fixture 自签、自批 |
| 上下文接近压缩 | 写当前卡 checkpoint、命令/结果/dirty/next step，切新窗口 | broad search、重读全仓、猜测遗漏 |
