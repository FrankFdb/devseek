## 1. 审计结论

本轮文档已形成一套可以指导下一阶段实施、可以被反证、也明确知道自己尚未证明什么的候选基线。最重要的结论不是“继续补更多高级功能”，而是：

> 先建立机器可复算的评测地基，再在一个未发布候选中完成 D-G01～D-G03 的单内核原子 cutover；所有 Surface、权限、workspace mutation、external effect、验证和完成事实共用同一语义边界。真实 Provider 只在冻结 wave 采集，正式顶级声明必须通过与开发集/RC 完全隔离的 L6 holdout。

审计判定为 **`direction-accepted-with-preconditions`**：

- 目标架构、能力目录、迁移策略和资格协议已足以决定下一迭代方向。
- 本目录尚未成为已生效 Active Architecture SSOT；需先落地 06 的 machine-readable ledger/migration manifest、批准 ADR，并给旧文档生成状态 banner。
- 当前代码仍是审计中描述的多 Loop/多 owner 状态；本轮没有修改实现，也没有取得新的 L4/L5/L6 证据。
- 当前 commit 的真实候选事实仍是 deterministic 通过、live CLI/plugin 未运行、`canary 0/3、medium 0/2、formal 0/1`，不得写 stable/top-tier。

## 5. 尚未证明和必须保留的风险

1. **实现未迁移**：本轮没有删除任何 Loop、writer、validator 或 completion owner；R1 只能在 Gate 0 完整通过后开始。
2. **机器事实源只完成 G0-A**：正式 capability ledger、milestone profile、R1 target manifest、generator 和默认 gate 已落地；签名 plan/session/preflight/attempt event、Evidence Manifest、独立 aggregator 与统一 Run Evidence Ledger 尚未实现。
3. **指标是目标规范，不是当前成绩**：04 的阈值必须变成版本化 profile 并取得 evidence，不能从文档直接生成 L 级。
4. **竞品与网页会变化**：公开页面、地区、计划、模型、DOM 或 Surface 改变会使对标/资格过期。
5. **平台范围有限**：首个 profile 可以只声明 Linux；Windows/macOS/WSL 未通过各自 conformance 前不能外推。
6. **外部授权待实际确认**：DeepSeek/Codex/Claude 的账号、自动化条款、数据出境和 fixture 权限必须在资格 session 中真实签署/记录，本文不代替法律或组织审批。
7. **密封评测需独立保管**：当前文档只定义 D/H 分仓、签名和职责分离；真正 H-* catalog/oracle 还不能交给实现者可见仓库。
8. **base model 与 harness 差距需消融**：native product profile 决定产品结果，diagnostic replay/同模型 profile 才定位 owner，不能用一个替代另一个。

## 6. 最少迭代达到目标的实施算法

“少迭代”不等于少验证，而是把昂贵且难定位的 live 反馈压缩成少量冻结 wave：

1. **Gate 0，一次建立测量地基**：G0-A 已落地 ledger/profile/target manifest 并降级旧 3/2/1 声明；继续按 G0-B/C/D 落地签名 Preregistration Plan、QualificationSession/Preflight/Attempt event、Evidence Manifest、独立聚合器和统一 Run Evidence Ledger。
2. **R1，一个未发布 Kernel 候选**：按 08 的 Slice A～D 处理 D-G01 create、D-G02 modify、D-G03 repair 和 D-G04 dirty worktree；中间只跑 unit/property/replay/Headless，不给用户安装混合架构。
3. **一次 Surface cutover**：所有 VS Code/CLI/声明入口同时经统一 Kernel，旧 semantic owner=0 后才 package/install；跑 L4 conformance 和一条 development natural-UI live 采集。
4. **R2，以只读工程脑减少返工**：先让工程定向、探索、指令、需求、外部 grounding 和设计进入同一 Kernel，再深化跨包实现/repair；避免先写错再靠更多修复轮补救。
5. **R3，只启用适用能力**：恢复、协作、memory、extensions 逐个原子晋级；Plugin/peer team/automation/computer use/headless SDK 没有产品宣称时保持 conditional/deferred，不为功能对称增加旁路。
6. **R4，一次冻结资格 wave**：先 3/2/1 RC 阻断明显回退，再用全新 disjoint L6 family 做盲评；任一修复产生新 candidate，不能补跑覆盖失败。

每个日常失败只采集一次完整 live trace，立即转 replay；修复唯一 semantic authority 后跑 dependency impact closure。只有 authority、profile/case/oracle、artifact/Surface/Provider 身份或冻结候选改变时，才扩大测试。这是减少 live、打包和正式项目次数的核心，而不是减少应有证据。
